## Contract and boundary

Closure signature introduction rejects repeated binding names (including `~:`)
before reading a saved signature or publishing descriptors/body signatures or
installing parameter locals. It shares declaration admission's bytes/span core.

claimed fixed by this parameter-group task.

## Source ownership and retained failure

A private Lower receipt retains the original closure signature's CoW Param array,
serial/span/body/signature identity and original Lower scope. On actual conflict
only, the producer checks original lexical owner, request session/root, active
owner and actual sourceControlNodePath. A current graph path alone cannot prove
origin: transplanting a real closure from another function was reproduced.

CheckingRequest is also constructed by Raw preparation. It is not owned-service
authority: direct Source emission was reproduced leaking through public
prepareLexicalBody. The producer therefore retains one ClosureSignatureRefusal
(Unclassified) with its proof/path in one failure array. The owned service
checks that stored result and interprets it as Source; it does not repeat name
comparison, a full graph walk or failed-builder parent lookup. Both owned
conversion points preserve reason, primary location and notes. This is one
shared producer/service-boundary frame, not an event dictionary per small rule.
It grants no semantic success or arbitrary diagnostic-promotion capability.

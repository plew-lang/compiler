# 言語セマンティクス（実装者が必ず押さえる点）

`SPEC.md` は構文を網羅する。本書は **文法だけでは分からない意味論** と、実装で間違えやすい点に絞る。背景・根拠は [design-decisions.md](design-decisions.md)、文法との差分は [grammar.md](grammar.md)。

## 設計の背骨（3点）

1. **参照の値渡し + GC + 所有権なし**。これが全制約の根。Rust 的な静的競合防止が効かないため、並行性は「spawn は全 immutable + チャネル」という Go 寄りの割り切りに着地している。
2. **拡張解決は呼び出し位置の `#Extension` だけで決定論的に決まる**。import スコープに依存しない。
3. **メタプログラミングはユーザー定義可能（方針転換中）**。当初は閉じていた（ユーザーマクロ無し、組み込み `@[...]` ディレクティブのみ）が、ビルドと独立した別コマンドで別ファイルにコード生成し、マクロは `TokenStream` を入出力する構造体（`Derive` トレイト実装）として定義する方式へ転換。組み込みディレクティブも理想的には同じ仕組みで提供する。詳細・未決は [spec/04-execution/16-metaprogramming.md](../spec/04-execution/16-metaprogramming.md) で検討中。

## 値の意味論

- すべての値の受け渡しは **参照の値渡し**（Java 的）。参照はコピーされるが参照先は共有される。
- 既定で不変。可変にするには宣言時 `mut val`、引数では `inout`。
  - `fn f(p: T)` → `p` は不変。フィールド代入・可変メソッド呼び出しは不可。
  - `fn f(inout p: T)` → `p` 経由で呼び出し元を書き換え可能。`mut` でなく `inout` を選んだのは「呼び出し元を書き換える」意図を明示するため。
- 不変変数を可変変数に代入するには `.clone()` が必要。
- **再宣言（shadowing）可**: 同名 `val`/`mut val` を再宣言できる（Rust 流・無制限）。再宣言は代入でなく**新束縛**で型・可変性を変えてよく、`name` は常にレキシカルに直近の宣言を指す。`guard`/`match`/`if` のパターンが同名で値を絞り込めるのはこの一般規則の帰結（特別扱いなし）。代入 `x = e`（既存 `mut` 束縛を同型で更新）とは別物。「同名で別物を指す」リスクは未使用束縛の lint で緩和。

## 文字列とコレクション（String / Array）

- **`String` は不変・UTF-8 常に妥当・`==` はバイト等価**。加工は新 String を返す。参照意味論で共有されるため不変が安全側（`spawn` の immutable キャプチャと整合）。正準等価は暗黙にせず、要れば明示正規化（API 未決）。
- **表現＝`struct String { pub(get) bytes: Array[U8] }`**。`s.bytes` は O(1)・ゼロコピー読み取り。任意バイトの公開生成は無し（リテラル＋検証 factory `from_bytes -> Result` のみ）で UTF-8 不変条件を守る。stored はフィールド公開・computed だけメソッド。
- **要素ビューは明示**：`bytes`（配列・ランダムアクセス・`count` O(1)）／`scalars()`・`graphemes()`（イテレータ・`count()` O(n)）。**整数添字 `s[i]` は無し**（生バイトは `s.bytes[i]`）。構築は伸長ビルダ→確定で凍結（連結 O(n²) 回避。ビルダ API 未決）。
- **`Array[T]` 一本**：動的・伸長・連続・プリミティブ unboxed。`arr[i]` は `Index[I32] -> T`、`count` O(1)。**`[E; N]`/const generics は無し**。**Slice（ビュー型）・substring・`Range`/`arr[1..4]` も当面無し＝すべて additive 保留**。FFI は境界コピー。
- **ラベル付きタプル（無名・構造的レコード）**：`(x: I32, y: I32)` 型・`(x: 1, y: 2)` 生成・`.x` 名前アクセス・`(val x, val y)=e` 分解。位置タプルは廃止（全要素ラベル必須）。構造的型・順不同・**振る舞いなし**（要れば名目 struct）・`()` はユニット。生成は名目=JSX／無名=`()` の2系統。同種列は `Array`。C 固定長配列は同型 `Array` にコピーで写す。
- **レンジ**：2 型 `HalfOpenRange`/`ClosedRange`（bare `Range` 不使用）。`a..<b`≡`<HalfOpenRange start=a end=b />`／`a..=b`≡`<ClosedRange start=a end=b />` の**固定糖衣**（普通の 2 フィールド構造体への JSX 構築＝配列/辞書のような JSX 例外ではない）。非トレイト・上書き不可・**両端を `<`/`=` で明示・素の `..` なし**。要素型は `T: Ord`（順序型なら任意 T・`contains`）、**Iterator は `T: Step`（離散・整数のみ・`Step: Ord`）で条件付き準拠**（F64 は反復不可）。優先度は算術より緩い。片側・`step`・レンジパターンは additive 保留。

## 並行性モデル

3 種のブロックを戻り値型で区別する：

```plew
val x = { give f() }         // 同期。ブロックは式（give が必要）→ T
val y = async { await ... }  // 非同期。Promise[T]。Node 式イベントループ
val h = spawn { give f() }   // マルチスレッド。ハンドル Thread[T]（暫定名）
```

- 基盤は **シングルプロセス・シングルスレッド + async/await + Promise**（Node 式）。**`spawn` で立てたスレッド自身も単一スレッド + イベントループ**（Web Worker 的に内部で async/await 可）。
- **`spawn` の戻りはハンドル構造体**（暫定 `Thread[T]`）で **`join() -> Promise[T]`**（`await handle.join()` で join。イベントループをブロックせず譲る＝async/await と同じ機構でスレッド完了を観測）。値を別スレッドから受け取る標準はこの `join`。detached（ハンドル未束縛）でもスレッドはブロックを完走（スレッド側に detached は不可視）。**ハンドルはスレッドを所有しない**（未束縛/GC でも死なない）。**ランタイムは全スレッド完了まで生存してから終了**（保留中の仕事を黙って切らない＝JS イベントループの自然な延長）。
- **`spawn` がキャプチャした値はすべて immutable 扱い（例外なし）**（元が `mut` でも spawn 内では不変）。チャネルの `Sender` も immutable にキャプチャされる ── 例外ではない。**保証は「spawn 内から spawn 外を書き換えない」＝書き込み隔離だけ**（spawn 外はロック不要）。**データ競合自由は提供しない**：spawn 外で可変な状態を spawn 間共有し未同期 read/write すればデータ競合＝**未定義動作になり得る**（将来の `Slice`/`any P`/enum の裂けでクラッシュ・メモリ破壊も）。idiomatic な並行コード（immutable キャプチャ＋チャネルで送信）は競合しない。可視性（外の変更が spawn 内 read に反映されるか）は**未規定**（native 共有・WASM コピーの両実装を許す）。理想は「クラッシュはしても UB なし（Go の concurrent map 検出型）」だが実装/ランタイムコスト次第で各機能の実装時に判断。
- **やり取りは「共有」でなく「送信」**（"share memory by communicating"）。可変状態を共有せず、immutable な `Sender` の **`send`（immutable メソッド）**で値を送る（バッファ操作はチャネル内部＝コアの責務、公開面は immutable）。`Mutex`/`sync val` は標準で提供しない。
  - 理由: 参照の値渡しゆえ、ロックでラップしても元の参照経由で競合し得る。構文・型レベルでは防げないと判明したため。`examples/main.pw` はこの競合をわざと示す例で、旧構文 `sync val` を使っており現行文法では解析できない。

## ブロックと `give`

- ブロックを **式として評価するには `give` 文が必須**。`val x = { 42 }` はコンパイルエラー、`val x = { give 42 }` が正。
- `if`/`match`/`loop` も式。`loop` は `break <expr>` で値を返す。

## 制御構造の意味論

- **`guard <cond> { … }`**: 条件が偽のときだけブロックを実行。本体は**発散必須**（早期 `return`／`break`／`continue`／`panic`）。enum の unwrap + 変数束縛が可能（`guard Result.Ok { value: val v } = r { return … }` の後 `v` が使える）。条件は下記の条件チェーン。
- **条件チェーン（`if`/`elif`/`while`/`guard`）**: 条件は `&&` 連結の節列で、各節は Bool 式 or 反証可能束縛 `PATTERN = expr`（Rust の let-chains 流）。左→右に短絡評価し、先行束縛は後続節と本体で有効。束縛節は `&&` のみ連結可（`||` 不可。Bool 節**内**の `||` は自由）。`if`/`while` も束縛可。ヘッダの `&&` は値レベル `&&` と同概念・別脱糖。Plew は構造体生成が JSX 限定なので Rust 流の「条件位置で構造体リテラル禁止」制限は不要。
- **パターンマッチング**: `match` の各ケースは式。enum バリアントの分解（`Color.Red { intensity: val intensity }`。位置フィールドは無く必ず名前付き）、ラベル付きタプル分解、`_` 既定ケース。**束縛は `val`／`mut val`**（bare はマッチ）・同名は punning（`{ val x }`≡`{ x: val x }`）。アーム右辺は 3 形式：ベア式 `=> expr`／ブロック `=> { …; give x }`／発散ブロック `=> { … panic … }`。
- **`panic "msg"`**: 発散する**文**（式ではない。`x ?? panic` は不可 → `guard`/`match` を使う）。回復不能なバグ用（回復可能な失敗は `Result`/`try`）、catch 不可、`spawn` 内 panic はプロセス全体を停止。**発散規則**：全経路が `panic`/`return`/`break`/`continue` で抜けるブロックは値を生まず `give` 不要で、`if`/`match` の発散アームとして任意の期待型と適合する（式全体の型は発散しないアームから決まる）。
- **構造化代入**: ラベル付きタプル `(val a, val b) = e`（`val`＝新規・bare＝既存へ代入、混在可）、構造体 `S { val field } = s`（型名先頭→ブロック非衝突）、入れ子可。未初期化宣言なし。

## エラーハンドリング

- **`try <expr>`** は `Result` 型の早期リターンのシンタックスシュガー（Rust の `?` 相当）。特別な例外機構ではない。
- エラー型は `From[Source]` 実装があれば自動変換される（`try` が `E.from(x: f)` を挿入。`ParseError` → `GeneralError` 等。ターゲットは関数戻り型から既知、ソース型でオーバーロード解決）。

## 型キャストと演算子＝トレイト

- **メソッドのオーバーロード**: 同名メソッドを引数型で区別して複数定義可（inherent/trait witness 問わず）。解決＝セレクタ（名前＋順序付きラベル）→ 具体位置の型。同セレクタ内は「型引数の形が全員一致・具体位置でのみ区別・制約は曖昧化に使わない」。**無名 impl が型のモジュールに閉じる**ので衝突検出はローカル（グローバルコヒーレンス不要）。重なり得るジェネリック impl は保守的拒否（specialization 無し）。
- **`x as T`** は `From` の糖衣（`x as T` ⟺ `T.from(x: x)`）。変換は**ターゲット側 `From[Source]`**（`assoc fn from(x: Source) -> Self`）。ターゲットは `as`／`try` で常に明示なので `from` はソース型でオーバーロード解決＝1 型が複数ソースから変換可。`try` のエラー変換も同じ `From`。
- **演算子はトレイト経由で解決**（`+`=`Add[Rhs]`, `[]`=`Index[Key]`, `??`=`Coalesce[Rhs]` …）。`a + b` ⟺ `a.add(rhs: b)` で `b` の型に対応する `Add[…]` conformance を選ぶ（オーバーロード）。型引数 `[..]` を持つのは**両辺が別型になり得る**演算（算術・添字・nil 合体・変換）。同じ右オペランド型に複数 conformance 不可、blanket と具体の併存不可（specialization 無し）。
- **等価・順序は同一型上の関係なので型引数なし**：`==`/`!=`＝`Eq { fn eq(rhs: Self) -> Bool }`（`!=` は `!(==)`、`@[Eq]` で derive）、`< <= > >=`＝`Ord: Eq { fn compare(rhs: Self) -> Ordering }`（4 演算子は `compare` に展開）。右辺は常に `Self`（異種比較 `impl A as Eq[B]` は対称・反射律を型で守れないため不可。`Ordering = Less|Equal|Greater`）。
- **`&&` / `||` は演算子トレイトではなく短絡する制御フロー**（`if` の糖衣 `a && b ≡ if a { give b } else { give false }`・Bool 専用・オーバーロード不可）。前置 `!`（`Not`）・`-`（`Neg`・符号反転、`-x`⟺`x.neg()`）は eager なのでトレイトのまま（`Neg` は型引数なし・符号付き整数/浮動小数のみ実装＝`U8`…`U64` は非実装で `-x` はコンパイルエラー）。ビット演算が要れば `&`/`|`＝`BitAnd`/`BitOr`（未提供）・ビット反転 `~`＝`BitNot`（未提供）。
- **`F32`/`F64` の NaN は比較で panic**：算術は IEEE（NaN/inf を生成）だが、`Eq`/`Ord`（`==`・`<` 等）が NaN に当たると panic する（静かな `false` を返さない）。判定は `is_nan()`。これで float も全順序 `Ord`・全等価 `Eq` に正直に準拠。inf は全順序を壊さないので通常値。
- **`/`・`%` の実行時意味（Rust/Go/Swift に合わせる）**：整数の 0 除算 `a / 0`・`a % 0` は **panic**（回復不能トラップ）。整数剰余 `%` は **truncated＝被除数の符号**（`-7 % 3 == -1`）。浮動小数 `/0.0` は IEEE の `inf`（panic しない）。`I32.MIN / -1` 等のオーバーフローは別途の整数オーバーフロー方針に従う（未決）。**`%`（`Rem`）は整数型のみ・float は非提供**（`1.5 % 0.5` はエラー＝Go/Swift に合わせる。剰余は名前付きメソッド。Rust は提供だが罠回避を優先）。
- **数値リテラルは多相・文脈で確定**: 組み込み数値型に多相で、注釈/引数/戻り/被演算子で一意に定まったもの。一意でなければエラー（既定型なし、`val x = 42` も文脈ゼロでエラー）。**負リテラルの先頭 `-` はリテラルの一部に畳み込む**（`Neg` ではない）＝`-128: I8`（最小値）が書ける（`(128).neg()` 経由だと `128` が I8 に収まらず溢れる）。`-x`（変数・式）は通常の `Neg`。

## 拡張システム（`#Extension`）

外部型・外部トレイトを安全に拡張するための中核機能。**型/意味論レベルの理解が実装に必須。**

- `impl MyStruct as Add[Rhs] { … }` = **無名実装**（ベア解決の対象）。`s + t` は `t` の型で対応する `Add[…]` にバインド（オーバーロード解決）。
- `extension MyExt { impl MyStruct as Add { … } }` = **名前付き実装**。`s#MyExt + t` のように呼び出し位置で明示指定された時のみ発動。
- **拡張で追加できるもの**: メソッド / 可変メソッド、関連値（`assoc val`）、型エイリアス、factory、`via` フィールドエイリアス、トレイト実装。**impl の主語は型でもトレイトでもよい**：`impl Type`／`impl Type as Trait`（型）に加え、`impl Trait`（派生メソッド・self: Self: Trait）／`impl B as A`（トレイト間準拠＝blanket・self: Self: B）も書ける（**トレイト主語の impl は拡張内のみ**・ベア不可）。**頭なし Self の blanket `impl[T] T` は禁止**（型所有が錨を持てず、型のベアメソッド一覧をローカル列挙できなくなる）。1 つの `extension` に複数 impl を束ね（型・トレイト混在可）、名前から中身は決まらない＝`value#P` は資格のある部分だけ活性化する **à la carte 適用**（`T#P` 自体は何の準拠も主張しない。`it.map()` には `#IterExt`〔ビュー〕＋`where T: Iterator`〔適用保証〕の直交 2 条件が要る）。
- **同名メソッド**: 引数型が違えば**オーバーロード**として共存（無名 impl 内でも可。ベア `value.foo()` は引数型で解決）。拡張は**同一シグネチャ**の同名も定義でき、`value#Ext.foo()` で `#Ext` シャドーイング。複数拡張を同時適用して同名・同シグネチャが衝突する場合はエラー。
- **型としての拡張**: `Person#FormalExtension` は「拡張適用済みの型」。`#!Ext` で拡張を外す（`person#!GreetingExtension#FormalExtension` で付け替え）。同名メソッドを持つ拡張の同時適用はコンパイルエラー。
- **拡張ビューは型の一部・実行時ゼロコスト・変更は明示**: `A#P` は表現上 `A` と同一（`a#P.m()` は単相関数の直呼び・`#P` は解決マーカ）。だが型検査では `A` の型細別＝**不変**に扱う。**暗黙キャストは持たない**：ビュー変更は呼び出し位置で `#`/`#!` を明示（`f(a: A#P)` には `f(a#P)`）。**コンテナ非伝播**（`Array[A]`/`Array[A#P]`・`Array[A#Ext1]`/`Array[A#Ext2]` は別型）＝`HashSet[A#Ext1]` を別ハッシュ `#Ext2` で読む論理バグを防ぐため不変に倒す。トレイト制約充足の拡張適用は `x#Ext` 明示（推論しない）。**拡張違いは別の具体型でオーバーロード共存**（暗黙キャストが無いので exact 一致・`default_extension` で `A≡A#P` のときのみ重複）。
- **デフォルト拡張 `default_extension #A#B`（型本体に宣言）**：型のベア表面に既定で載せる拡張。既定拡張のメソッドはベア解決に参加（非デフォルト拡張は `#Ext` 必須）。宣言できるのは型の作者のみ（型本体＝型所有モジュール、外部から他人の型のベア表面は変えられない）。衝突（own メソッド／別の既定拡張と同セレクタ・同シグネチャ）は**宣言地点でエラー**＝作者が curate。`#!Ext` で剥がせる・`#Ext` は常に届く（`Array` ≡ `Array#IterExt#FooExt`）。適用は à la carte。**ジェネリックには流れない**：境界 `T: Trait` は要求しか運ばないので、境界型変数の派生メソッドは `x#Ext`（または引数型 `x: T#Ext`＋別途 `where`）で明示。これが「提供メソッド廃止＋extension/default 一本化」でベア提供メソッドのチェーン利便を回復する仕掛け。
- **拡張メソッド内の `self` の型 = `Foo#Bar`**（対象型 + その拡張）。本体は一度だけ型検査されるので self は固定型で、`Bar` が定義時に知るのは対象型 `Foo` と自分 `Bar` だけ。呼び出し側が追加で別拡張を効かせていても（`v: Foo#Bar#A`）本体内 self は `Foo#Bar`＝**呼び出し側の `#A` は本体から不可視**（モジュラ型検査のため）。帰結：`self.m()` は `#Bar` ビューで元をシャドーする**再帰**（元メソッド呼びではない）、**元へは `self#!Bar.m()`**（唯一の経路・"super" 相当）、別拡張再利用は `self#A.foo()`（明示スタック・衝突なら `self#!Bar#A`）。可視性は字句的で self 型に依らず（拡張 impl 内は pub/pub(get) のみ）、`self#!Bar` は解決先のみ変え可視性は広げない。
- 設計目標は「import を見なくても **呼び出し位置だけで定義場所が分かる**」こと。**継承・ネストは禁止**（単一ディスパッチ解決＝由来一意性を壊すため。再利用は `self#A.foo()`、組み合わせは `value#A#B`、bundling 別名 `alias Web = Json+Http` は将来候補）。re-export は一般シンボルと同じく許可（→ [design-decisions.md](design-decisions.md) の Single Dispatch Resolution Rule）。

## トレイト定義（要求のみ・派生メソッドは拡張へ・継承）

- **トレイト本体＝要求だけ（全部本体なし）**：フィールド/メソッド/関連値/関連型。各型が `via`／本体で witness。**派生メソッド**（`map`/`filter` を `next` の上に組む類＝`.map().filter()` チェーンの土台）はトレイト本体にもベア `impl Trait` にも書かず、**名前付き拡張の `impl Trait { … }`** に置き、各型が `default_extension #Ext` で取り込む（→ 拡張システム）。`impl Trait`（拡張内）の `self` は準拠型 `Self: Trait`、要求・同拡張内の他メソッドを呼べ、本体は一度だけ型検査。**ベアの `impl Trait` は廃止**（旧「提供メソッド」を撤回。トレイト主語の impl は拡張内のみ）。
- **派生メソッドは自動では生えない（opt-in）**：型が `default_extension` で取り込むか使用箇所で `value#Ext` 明示。準拠側 `impl Type as Trait` が witness するのは要求だけで上書き不可（挙動を変えたい型は別拡張＋`#Ext`）。「上書き可能な既定」は持たない（Swift protocol extension の静的/動的ディスパッチ食い違い回避）。衝突＝**型の `default_extension` 宣言地点**で検出（own メソッド／別の既定拡張と同セレクタ・同シグネチャ→エラー、引数違いは共存）。型作者がデフォルト集合を curate して解決。
- **継承 `trait Sub: Super`**：Sub 準拠は Super 準拠を要求（`:` は `where` と同じ制約）。**複数指定は `+`**（`trait Sub: A + B`・`trait Sub: Iter[Item=X] + Clone`）＝`where T: A + B` と同じく同一主語 `Self` に制約を重ねる（`,` は別主語の並びで supertrait では使わない）。**制約であって自動実装ではない** — `impl T as Sub` には別途 `impl T as Super` が要る（暗黙生成なし＝暗黙準拠を持たない方針の一貫）。Sub を対象にする拡張の派生メソッドは self 経由で Super の要求を呼べる。ダイヤモンドの同名**要求**はオーバーロード集合に入り同シグネチャなら畳まれる（不一致は共存・衝突ならエラー）。**派生メソッドはトレイトに自動付随しない**ので、別経路由来の同名・同シグネチャ派生メソッド衝突は「型が両方をデフォルトに含めたとき」だけ＝**その型の `default_extension` 宣言地点**で報告（トレイト定義が衝突を強制する旧 (1)/(2) の検出時点分岐は不要になった）。
- **トレイト型引数あり（多重 conformance）＋関連型（出力）**：入力＝呼ぶ側が選び 1 型に複数 conformance あり得るものは型引数（`Add[Rhs]`：`Vec` は `Add[Vec]` と `Add[F64]` 両方に準拠）。出力＝impl が一意に決めるものは関連型（`type Output`・`Iterator.Item`）。両方持てる。複数 conformance のメソッドは引数型で区別されるオーバーロードになる。ただし等価・順序（`Eq`/`Ord`）は同一型上の関係なので型引数を持たない（右辺常に `Self`）。
- **関連型 `type Item`**：宣言は `type Item`、シグネチャ中はベア参照、impl は `type Item = X` で束ねる（`via` 不使用）、制約可（`type Item: Format`）。関連型は**型の名前空間**（メソッド/フィールドのオーバーロード集合とは別）。外部射影は `T.Item`（`.`）。トレイト名の `[...]` は**位置型引数＋関連型束縛**の混在（`Add[Vec]`／`Iterator[Item = Foo]`、Rust の `Trait<Arg, Assoc=T>` 同形。supertrait/where/引数境界共通）。

## トレイトを値型にする存在型（`any`）

- **`any P` だけが存在型**（型消去・動的ディスパッチ・**異種混在**）。裸の `P` は型位置に置けない。`Array[any Drawable]` に別々の具体型を混ぜられる（React 風 children が動機）。`any P` は第一級の型＝変数・フィールド・引数・戻り値・ジェネリック引数・関連型束縛・newtype underlying のどこでも可。**`some`/opaque は持たない**（戻りも `any P`）。`dyn` でなく `any` 採用＝「動的ディスパッチ」（実装語）でなく「準拠する任意の型」（概念）を指し everyday に読める。
- **ジェネリックと別物**：`fn f[T](x: T) where T: P`（同種・静的・**全要求**が使える＝`Eq`/`Ord`/`From` も）vs `fn f(x: any P)`（異種・動的・呼べるメンバに制限）。横着すると後者を書きがちだが能力が違う。
- **形成は全型引数・全関連型を束縛必須**：`any Iterator` は Error、`any Iterator[Item = I32]` / `any Iterator[Item = T]`（T はジェネリック）は OK。`any Add` は Error、`any Add[I32, Output = I32]` は OK。これで `any P` 内で消去が残るのは **`Self` だけ**（関連型は具体型に確定）。
- **呼べる/呼べないはメンバ単位・使用箇所で診断**（型レベルの一律禁止なし＝modern Swift SE-0309 と同方向）。呼べる＝`self` を受け `Self` は出力位置のみ（出力 `Self` は `any P` に再消去・`clone() -> Self`→`any P`、関連型は確定済みなので入力に出ても可＝`any Add[I32,Output=I32]` の `add(rhs:I32)` は呼べる）。呼べない＝(a) `Self` が**非レシーバ入力位置**（`Eq.eq(rhs: Self)` → `a == b` がその行でエラー）、(b) **関連関数・factory**（レシーバ無し＝witness 運べない）。全要求が呼べない `any P`（`any Eq` 単独）は valid だが lint で警告。
- **実装は最終フェーズ**（動的ディスパッチ機構が要る）。仕様は確定。動機＝Plew = *Programming Language for Everyday Wizard*（トレイト配列を Swift のように素直に書ける）。

## トレイト準拠と `via`（全要求を明示）

- 型のメソッド・フィールドはセレクタ（名前＋ラベル）ごとの**オーバーロード集合**（同一シグネチャは一意・引数型で区別）。準拠は `impl Type as Trait` で明示宣言し、**各要求を `via` で実体メンバに束ねる**か、メソッドはその場で本体定義する。
- **全要求に `via` を明示**（`via` 左辺は**常に完全シグネチャ**＝メソッドは引数ラベル・型・戻り型、フィールドは型。名前一致でも省略不可）。本体定義形と対称で、同名要求が複数あっても一意に特定できる（特例なし）。空の impl は準拠失敗。これで「名前が合うだけで勝手に witness になる」うっかり準拠を排除（Swift の暗黙 witness の危険を回避しつつ、Rust の 2 名前空間の曖昧さも回避する第三の解）。
- **別名はベアでも呼べる**: `fn draw via render` は要求名 `draw` をベアの呼び名にも加える（`x.draw()` も `x.render()` も同じメソッド）。同セレクタ・同シグネチャの既存メンバと衝突すればエラー（引数違いはオーバーロードとして共存）。
- **define-once**: メソッド本体定義は inherent か 1 つの trait impl のいずれか一箇所のみ、他は `via` 参照。フィールドは struct 宣言で定義し trait impl では `via` で束ねるだけ（trait impl はフィールドを新設しない）。
- **シグネチャ一致**必須、不一致はエラー。**1 つの実体メソッドが複数トレイトを witness 可**。同名・**同シグネチャ**で別挙動が要るときは名前付き `extension` + `#Ext`（引数違いはオーバーロードで足りる）。
- トレードオフ: フィールド要求トレイトは、フィールドを後付けできない外部型には（無名 impl では）実装できない。

## モジュールと無名 impl の配置（`part`）

- **モジュール = インポート可能なルートファイル + `part` で推移的に綴じた全ファイル**（forest。1 ファイルは高々 1 親、循環不可）。`part` は片側宣言（綴じられる側は無印）、ネスト可、ディレクトリ跨ぎ可。part 先は独立 import 不可（外部に見えるのはルートだけ）。`import` は別モジュールを参照、`part` は同一モジュールに綴じ込む、と役割が別。
- **モジュール内はスコープ共有**（互いを import 不要）。ただし**外部依存の import はファイルごと**に書く（暗黙の可視性は「明示的に綴じたツリー」内に限定。これがディレクトリ境界の暗黙性を嫌った答え）。
- **無名 impl `impl T as Tr` は T を定義したモジュール内にのみ置ける**（Rust の「型 or トレイト」より厳格な型所有版）。同一モジュール内の重複はエラー。**外部型への実装はトレイト所有を問わず無名では不可で拡張（`#Ext`）を使う**（自分のトレイトを外部型に実装する場合も拡張）。
- モジュールを import すると型・トレイトとその無名 impl が同伴して入る。impl 単独の import は存在しない。

## メンバの可視性（型スコープ）

- メンバ（フィールド/メソッド）の可視性は**型のカプセル化のみ**を制御し、モジュール/パッケージ境界とは独立（境界は `export` / 再エクスポート）。段階は 2 つだけ（`pub(crate)` 等の中間段なし）。
- `pub`＝型を見られるコードから可視。`pub(get)`＝読み取り pub・書き込みは内部のみ。**非公開（修飾なし）＝その型の無名 impl からのみ可視**（同一モジュールの非 impl コード・名前付き拡張・他型・外部、いずれも不可）。
- 帰結：拡張（`#Ext`）は対象型の pub のみ見える＝外部型を拡張しても内部に触れられず `pub` が無力化しない。兄弟モジュールが触りたいメンバは `pub` にするか、`part` で型のモジュールに同居させて無名 impl から触る。

## 関連関数 / 関連値（`assoc`）

- Plew の static メソッド/変数は `assoc fn`/`assoc val`（名前が違うだけで static と同等。型名で呼ぶ）。当初「static 不要・グローバル関数で足りる」としたが**翻意**。型に属さないトップレベル関数も別途あるが static の代替ではない（両方存在）。**ユーザーは ambient／グローバルな定義を作れない**（全定義はモジュールスコープ・他モジュールは `import` 必須。"グローバル名前空間が無い" のではなく、唯一の ambient＝言語提供 lang item にユーザーが足せない、という話）。トップレベル変数（`val` 定数・`mut val` 可変）も持てる。
- 型名で呼びたいものは `assoc fn`（関連関数）/ `assoc val`（関連値）。`self` は参照の値渡しのため Rust の `&self` 明示は不要。
- **言語アイテム（lang item）は常にスコープ・それ以外は明示 import**: no-primitives ゆえ、構文が意味として参照する型/トレイト（数値型・`Bool`・`String`・`Array`・`Optional`・`Result`・レンジ 2 型・`Promise`/スレッドハンドル・`Add`/`Eq`/`Ord`/`From`/`Iterator`/`Step` 等＝`1`/`"x"`/`[..]`/`a..<b`/`x?`/`try`/`+`/`for` の脱糖先）は import 不要で常にスコープ＝キーワード同格の言語の語彙。**それ以外（`Random`/`HashMap`/`print` 等）は明示 import**（構文が参照しない＝lang item でない）。唯一の ambient は言語提供 lang item でユーザーは足せない（"グローバル名前空間なし" ではなく "ユーザーが ambient を作れない"）。出どころは「ローカル→ファイル import→lang item」。lang item 名はローカル shadowing で覆える。正確な lang item 一覧は TODO。マニフェスト既定 import（write-once）は当面不採用（additive）。

## 構造体インスタンス化（construct / JSX ライク）

- **全ての構造体は JSX ライクな `<Type field=expr />` でのみ** インスタンス化する。
- 属性値は常に式なので JSX の `{}` は不要（複雑な式は括弧で囲む）。子要素を持てる（`<Container>…</Container>`）。

## ジェネリクス / where 句

- 基本的に Rust 同様 **不変（invariant）**。
- **型パラメータの `[...]` は名前のみ**、制約は全部 `where`（インライン `[T: Trait]` なし）。`where` の述語は `型: 制約` のみで**型等価 `where T = I32` は持たない**（具体実装は型位置 `Struct[I32]`、関連型束縛は `T: Iterator[Item = I32]`）。impl 導入の型パラメータは **`impl[...]` で前置宣言**（`impl[T] Struct[T] as Trait where T: Format`）。デフォルト型引数なし。「トレイト境界」は**「トレイト制約」**と呼ぶ（`境界`=boundary は温存）。

## 命名規則（言語仕様として強制）

- 型名: PascalCase。変数・関数名: snake_case。enum バリアント: PascalCase。
- import のパスコンポーネント（ファイル/ディレクトリ名）は PascalCase 必須（`.`/`..` のみ例外）。

## 標準トレイト / ディレクティブ

- 基本: `Clone`, `Hash`, `Format`（表示・補間）。変換: `From[Source]`（`x as T`⟺`T.from(x:x)`・`try` のエラー変換にも使用）。演算子で**型引数ありは別型を結ぶもの**: 算術 `Add[Rhs]/Sub[Rhs]/Mul[Rhs]/Div[Rhs]/Rem[Rhs]`（`+ - * / %`・`type Output`・`**` は不採用で `pow`・ビット演算/シフトは未提供）・添字 `Index[Key]`・nil 合体 `Coalesce[Rhs]`・単項 `Not`／`Neg`（`Neg`＝符号反転・型引数なし・符号付き整数/浮動小数のみ）。**等価/順序は型引数なし**: `Eq{eq(rhs:Self)->Bool}`（`==`/`!=`）・`Ord: Eq{compare(rhs:Self)->Ordering}`（`< <= > >=`）。**`&&`/`||` はトレイトでなく制御フロー**（`if` 糖衣・短絡）。`Ordering = Less|Equal|Greater`。
- `@[...]` 組み込みディレクティブ（コンパイラが自動合成。命名は型由来で **PascalCase**）: `Eq`, `Hash`, `Clone`, `Decode`, `Encode`、struct 専用 `DefaultFactory(pub)`、enum 専用 `All`（`Enum.all()` を生成）。ユーザー定義メタプログラミングは別章（→ [spec/04-execution/16-metaprogramming.md](../spec/04-execution/16-metaprogramming.md)）。

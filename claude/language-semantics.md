# 言語セマンティクス（実装者向けダイジェスト）

`SPEC.md`／`spec/*.md` が**意味論まで含めた正典**（機構の詳細と例はそこにある）。本書はそれを実装者向けに再構成したダイジェストで、**機構を再掲せず**次の二つだけに絞る：

1. **章をまたぐ設計の背骨** — 個々の spec 章には現れない、決定どうしの繋がり。
2. **実装で間違えやすい罠** — spec を素直に読むと取りこぼす／逆に取りやすい点を、spec の該当箇所へのリンクつきで。

各判断の根拠・却下案・未決は [design-decisions.md](design-decisions.md)、文法との差分は [grammar.md](grammar.md)。**詳細を知りたくなったら必ずリンク先（spec が正典）へ。**

## 設計の背骨（3点）

**最上位の拠り所（迷ったらここへ・全文は [CLAUDE.md](../CLAUDE.md) / [spec/01](../spec/01-basics/01-overview.md)）**：*唱えた通りに発現する。仕組みは問わない*（意味は唱えた通り＝忖度しない・曖昧はエラー／仕組み＝CoW・ARC 等は隠蔽してよい）。二軸＝**(1) 意味は唱えた通り（透明）**：意味を決める層（字句/名前/型/オーバーロード/トレイト/変換の解決）でコンパイラは勝手をしない＝**補完はする／忖度はしない／曖昧はエラー**。**(2) 発現は隠蔽してよい（コストは裏）**：最適化・codegen・ARC・CoW・スケジューリングや「人間に難しすぎる魔法」は自由に隠す。境界は「コンパイラ vs ランタイム」ではなく「**意味の決定 vs 発現**」＝**hidden cost は可・hidden meaning/behavior/provenance は不可**。下の 3 点とすべての罠はこの拠り所の帰結。


1. **値意味論 + CoW + ARC + opt-in 所有権**。これが全制約の根（→ [spec/03](../spec/01-basics/03-values.md)）。代入・受け渡しは独立コピー（CoW で遅延）・共有可変は `Ref` のみ・メモリは ARC（循環は `WeakRef`）。`val` の不変性が信頼でき、並行性は「借用は async/spawn 境界を越えず・spawn は move/copy のみ・`Ref` は spawn 不可」で**実質 race-free**（→ [spec/14](../spec/04-execution/14-concurrency.md)）。文字列の CoW 不変性・`Mutex` 非提供・拡張の値非改変・`deinit` による決定的な資源解放なども、ここから演繹的に出てくる。
2. **拡張解決は呼び出し位置の `#Extension` だけで決定論的に決まる**。import スコープに依存しない（→ [spec/09](../spec/02-type-system/09-extensions.md)）。実装上は「素の呼び出し＝無名 impl＋**準拠トレイトの提供メソッド**＋型の既定拡張のオーバーロード集合／`#Ext`・`#P` を書いたときだけそのビュー／源を開く」。一意に定まらなければコンパイルエラー（同名提供メソッドの衝突は併存可・曖昧なベア呼びだけがエラー＝`a#P.foo()` で選ぶ）。
3. **メタプログラミングはユーザー定義可能（方針転換中）**：ビルドと独立した別コマンドで別ファイルへコード生成し、マクロは `TokenStream` を入出力する構造体（`Derive` 実装）。実装はコンパイラ完成後の最後（→ [spec/16](../spec/04-execution/16-metaprogramming.md)）。

## 実装で間違えやすい罠（spec 索引つき）

トピックごとに、spec を読むだけだと踏みやすい点だけを挙げる。**機構そのものはリンク先が正典**。

### 値・束縛 → [spec/03](../spec/01-basics/03-values.md)
- すべて**値意味論（CoW）**（代入・受け渡しは独立コピー・共有可変は `Ref` のみ）。可変記憶域は `mut val`／アクセスは `borrow`/`inout`/`move`（呼び出しもモードを echo）→ [spec/03](../spec/01-basics/03-values.md)。`unique`/`local`・`Ref`/`WeakRef`/`->`・`deinit` も同章。
- **deinit の破棄順（決定的）**：型自身の `deinit` 本体が先（全フィールド有効）→ フィールドは**宣言順（上から下）**・入れ子は再帰同規則。フィールド既定値が他フィールド非参照ゆえ構築依存が無く、C++ の逆順動機が無い（最単純な宣言順）→ [spec/03 deinit](../spec/01-basics/03-values.md#deinit)。
- **newtype が unique を包むと自動 unique**（再宣言不要・`deinit` 継承・一度だけ実行）。コピー可能化＝唯一所有回避＝資源安全破壊ゆえ伝播必須。underlying が単一可視なので構造体の見落とし罠が無い → [spec/10 unique 型を包む](../spec/02-type-system/10-newtype.md#unique-型を包む)。
- **`mut val` の合成規則（Swift と同じ・罠）**：フィールド書き換え・`inout fn` 呼び出しには **束縛が `mut val`** かつ **フィールド自身が `mut val`** の**両方**が要る。`val c = <Counter n=0/>` の `c.n += 1` はフィールドが `mut val` でもエラー（束縛が `val`＝値型は束縛単位で凍結）。Ref だけがこの例外（`val` 束縛越しでも referent を変更可）→ [spec/03](../spec/01-basics/03-values.md#変数宣言val--mut-val)。
- **クロージャは参照キャプチャ（罠：spawn だけ別）** → [spec/04](../spec/01-basics/04-functions.md#環境のキャプチャ)。通常の閉包は外側変数を**参照でキャプチャ**（Swift と同じ）＝`mut val` キャプチャは**可変・外と共有・呼び出しをまたいで永続**（`mut val x=1; val h=fn(){x+=1}; h(); ⇒ x==2`）。脱出（escaping）しても変数は閉包の生存中存続するので**状態を持つ閉包に `Ref` は不要**（`makeCounter` は `mut val n` の参照キャプチャだけで書ける＝Ref 版は誤り）。`val` キャプチャは読み取り専用。単一スレッド（イベントループ）ゆえ同時アクセスは起きず論理 interleave のみ。**`spawn` だけが不変キャプチャ**＝境界越えは copy/move のみで、`mut val` を参照キャプチャした閉包は spawn 不可（`Ref` を含む値と同じ `local` 扱い）。`unique` はキャプチャ不可。**`Ref` の動機は閉包ではなく unique 値の共有・意図した循環**（[spec/03](../spec/01-basics/03-values.md)）。注：「共有可変は `Ref` のみ」はヒープ上の**第一級の共有可変値**の話で、レキシカルな `mut val` のクロージャ参照キャプチャも共有可変だが**単一スレッド限定・spawn 不可**の別機構。
- **再帰的な値型は自動箱化（罠）** → [spec/05](../spec/02-type-system/05-structs-enums.md#再帰的な値型)。自己参照する `struct`/`enum`（木・連結リスト・AST）は素朴にはサイズ無限。コンパイラが再帰を検出し**必要なフィールドを CoW ヒープセルで自動箱化**（Array/String と同じ機構）してレイアウトを有限化する。`indirect` 等の修飾語なし／**フィールド型・値意味論は書いた通り（ラッパー型は表面に出ない）**／間接箇所はコンパイラが選ぶ。`Ref` は使わない＝値意味論のまま `local` にならず spawn 可。**値意味論の再帰型は循環を作れない**（親への貼り戻しは `Ref` 必須）ので `WeakRef`/リーク問題は生じない。`Ref` を書くのは共有可変グラフを意図したときだけ。終端ケースなしの再帰（`struct Node { val child: Node }`）は型として合法のまま（構築不能なだけ＝不要なチェックを課さない）。codegen の罠：箱の挿入＝CoW セル割り当て・spawn 境界では eager 実体化が連鎖（→ 並行性節）。
- **再宣言（shadowing）は無制限**で、`name` は常にレキシカルに直近の宣言を指す。`guard`/`match`/`if` の絞り込みはこの一般規則の帰結＝**特別扱いしない**（代入 `x = e`＝既存 `mut` の同型更新とは別概念）。
- **未初期化宣言は無い**（確定代入解析を持ち込まない）。`val x: T` 後分岐代入は `val x = if … { give … }` で書く。
- **場所（place）越しの変更は get-modify-set（罠）** → [spec/03](../spec/01-basics/03-values.md#場所place越しの変更)。`arr[i].field = x`・`arr[i].inoutMethod()`・`a.b[i].c = x` は**可変参照を返さず**、添字段＝`Index`(読)+`IndexSet`(書)・フィールド段＝load/store の **read-modify-write** に脱糖（複合代入の一般化・場所は 1 回評価・`IndexSet` 無い型は変更不可）。**これが意味モデル**で、in-place 直接書き換えは「一意所有＋無効化なし＋非重なりを静的に証明できる時だけの観測不能な最適化」（実行時アクセス計装は持たない＝コピーは dangling しないので不要・将来 Swift 流 in-place+トラップは additive で非破壊）。**重なる `inout`**（1 呼び出しで 2 つ以上の inout 位置が同じ場所＝レシーバ＋引数等）は **last-write-wins で片方が静かに消えるバグ**ゆえ**プログラムエラー**＝①構文同一→コンパイルエラー ②添字が distinct 証明不可→lint＋限定ランタイム panic ③distinct 証明可→OK（last-write-wins 挙動は*保証しない*＝将来の実装変更に備える）。**`inout` の排他はスレッド安全でなく単一スレッドのメモリ安全（再確保による dangling 防止）の話**＝Swift の Law of Exclusivity と同根拠だが、Plew はコピー意味論ゆえ全アクセス計装が要らない。

### ブロック・制御フロー → [spec/11](../spec/03-expressions/11-control-flow.md)
- ブロックを式にするには **`give` 必須**（`val x = { 42 }` はエラー、`{ give 42 }` が正）。`if`/`match`/`loop` も式（`loop` は `break <expr>`）。
- **`match` は網羅必須（Rust 流）**：全値がいずれかのアームに当たらないと**コンパイルエラー**（式なので結果値の無い経路を許せない）。enum は全バリアント・`Bool` は両方・整数/`String` 等の開いた型は `_`（or 捕捉束縛 `val x`）必須。**上から順・最初の一致のみ**（fall-through なし）、到達不能アームは警告。**アームにガードは無い**ので網羅判定は純粋に構造的（Rust の「ガード付きは網羅に数えない」例外が不要）。発散アーム（`_ => panic`）もパターンはカバーに数える。
- **`panic` は発散する文**（式ではない＝`x ?? panic` 不可）。全経路が `panic`/`return`/`break`/`continue` で抜けるブロックは値を生まず `give` 不要で、任意の期待型に適合する（`if`/`match` の発散アーム）。`spawn` 内 panic はプロセス全体を停止。
- **`panic` は abort＝`deinit` を走らせない（罠）** → [spec/11](../spec/03-expressions/11-control-flow.md#panic-と発散)。スタックを巻き戻さず trap 一発でプロセス停止（unwind テーブル/landing pad 不要＝Rust `panic="abort"`・Swift の `fatalError`/`precondition` trap と同じ。`throws`/`try` 経路の deinit 実行とは別物）。catch 不可ゆえ unwind しても回復せず、壊れた不変条件下で deinit を走らせると二次災害（壊れたデータ書き込み・二重 panic）になるため。資源は OS が回収。**`deinit` の決定的解放契約は正常終了パス（スコープ離脱・`return`・`try`/`Result` 伝播）のみ**で、panic はその外。死ぬ前のログ flush 等が要れば将来 atexit 風フックを additive に。
- **条件チェーン**：`if`/`elif`/`while`/`guard` の条件は `&&` 連結の節列で、各節は Bool 式 or 反証可能束縛 `PAT = expr`（Rust let-chains 流）。束縛節は `&&` のみ（`||` 不可・Bool 節内の `||` は自由）。`guard` 本体は発散必須。
- 束縛は `val`＝新規・bare＝既存。refutable（`match`/`if`/`while`/`guard`）は bare＝マッチ。punning `{ val x }`≡`{ x: val x }`。名前位置の葉は 3 種＝`val x`（新規）／bare `x`（既存マッチ）／**`_`（破棄）**。
- **`_` は一般ワイルドカードパターン**（match 専用でなくパターン位置ならどこでも・`Some { value: _ }`・`(val x, _)`）＝束縛を作らない破棄・**書き込み専用シンクで値式不可**（`val x = _` 不可）。**構造体/レコード/バリアントを開く分解は全フィールド明示必須**（束縛 or `_`・残り無視 `..` なし）＝Rust の「全フィールド or `..`」から `..` を抜いた形で、フィールド追加時に既存パターンがエラー化し静かな取りこぼしを防ぐ。

### 型・メソッド解決 → [spec/07](../spec/02-type-system/07-methods-impl.md), [spec/06](../spec/02-type-system/06-generics.md)
- **メソッドはオーバーロード可**：セレクタ（名前＋順序付きラベル）→ 具体位置の型で解決。同セレクタ内は「型引数の形が全員一致・具体位置でのみ区別・制約は曖昧化に使わない」。**無名 impl が型のモジュールに閉じる**ので衝突検出はローカルで完結（グローバルコヒーレンス不要・重なり得るジェネリック impl は保守的拒否＝specialization 無し）。
- **メソッドは値に代入不可（罠）**：`val f = obj.method` は禁止＝**クロージャで包む**（`fn(value:){ obj.method(value:) }`）。(1) どのオーバーロードか一意でない、(2) `self` のアクセスモード（borrow 脱出不可・inout/move/unique-self 持ち回り不可）を、クロージャ内呼び出し＋[参照キャプチャ規則](../spec/01-basics/04-functions.md#環境のキャプチャ)が専用規則ゼロで解消（関数型ラベルの方針と一貫）。セレクタ糖衣 `obj.method(value:)` は additive 保留 → [spec/07](../spec/02-type-system/07-methods-impl.md#メソッドは値に取り出せないクロージャで包む)。
- **デフォルト引数（`arg: T = 式`）は呼び出しごとに再評価**（Python の定義時 1 回共有ではない＝`= []` は毎回フレッシュで参照共有の罠なし）。式は**定義側モジュールのスコープ**で評価（呼び出し側の名前ではない・非公開も参照可）・**他引数や `self` は参照不可**（自己完結・評価順依存を持ち込まない）・任意の実行時式可（const 限定でない）。**ラベル必須ゆえ末尾限定なし**（途中だけ省略も一意）。`inout` 引数は不可。**省略の組み合わせごとに呼び出しセレクタが増え**（`f(a:b:)`＋`f(b:)`）通常のオーバーロード集合に合流＝別宣言と型で区別できない衝突はコンパイルエラー。 → [spec/04](../spec/01-basics/04-functions.md)
- **関数型のラベルは型同一性の一部（罠）** → [spec/04](../spec/01-basics/04-functions.md#ラベルは型の一部厳密な同一性暗黙変換なし)。`fn(value: I32)->T` と `fn(element: I32)->T` は**別型**でサブタイプも暗黙変換も無い（引数順固定＋暗黙変換なしで Swift SE-0111 の混乱＝並べ替え＋暗黙サブタイプを回避しつつラベルを型に残す）。**クロージャリテラルの引数名＝ラベルで期待型と順序込み完全一致必須・ラベル多相なし**（`f(handler: fn(y:,x:){…})` を `fn(x:,y:)` 期待に渡すと silent swap せず**型エラー**）。型推論は型注釈だけ埋めラベルは埋めない。ラベル違いの適応は**明示クロージャラッパー**（`fn(element: I32){ return double(value: element) }`）。ゼロコスト relabel キャストは持たない（`as` relabel は将来 additive・許容を増やすだけで非破壊。多相は逆にオーバーロード下では後付けが破壊的）。**ラベル抑制 `name~: Type`**（`~` は単項 BitNot 専用ゆえ name 直後の `~` は一意にラベル抑制マーカー＝式と非曖昧）＝その引数を無ラベル化＝位置渡し。既定は常にラベル付き・`~:` 明示時のみ無ラベル（1 引数の自動省略はしない＝`delay(seconds:)` を守る）・混在自由・順序は宣言順・**リネーム無し**（2 状態）。関数型の無ラベル位置は**裸の型**（`fn(String, terminator: String)->()`）でクロージャ側も `~:` で一致必須。**`factory` では `~:` 不可**（生成は JSX `<Type label=…/>` でラベル付きが生成可視性の根幹）。記法経緯（`_ x` の二トークン rename 形回避・`::` は Rust/C++ 連想で却下・`x~:` は衝突ゼロで採用）は [design-decisions.md](design-decisions.md)「関数型ラベルの型同一性」。
- 型パラメータ `[...]` は**名前のみ**・制約は全部 `where`（述語は `型: 制約` のみ・型等価 `T = I32` は無い）。impl 導入の型変数は `impl[T] Type …` と前置宣言。

### 数値リテラル・演算子 → [spec/02](../spec/01-basics/02-basic-types.md), [spec/12](../spec/03-expressions/12-operators.md)
- **数値リテラルは多相・文脈で確定・既定型なし**（一意でなければエラー＝`val x = 42` も文脈ゼロでエラー）。**到達範囲は局所（前方・双方向）＝変数の後続使用から宣言型を逆算する大域推論（単一化/HM）はしない**（アドホックなオーバーロードと衝突→曖昧化＋コンパイル時間爆発＝Swift の `ExpressibleByIntegerLiteral`×オーバーロードと同型。最小コンパイラ優先）。**許容する帰結**：`for val i in 0..<10`・`1 + 1` 等は素だとサフィックス必須（`0..<10U64`/`1I32+1`）。暗黙数値変換なし＋添字/`count`=`U64` 固定ゆえ単一の既定型では添字(U64)と算術(I32)を両立できない＝既定型を置けない核心。**緩和は additive**（(a) 文脈ゼロ時限定フォールバック＝**符号付きのみ `I32`/`I64`・`U64` は型の嘘ゆえ不可**、(b) 局所→大域拡張。どちらも今エラーの箇所が通るだけで既存意味不変）ゆえ初手は厳しい側。**comptime_int・I64 添字も探索の上却下**（design-decisions「却下した代替」）。生成物の実行コストは無関係（型は消える）。
- **負リテラルの先頭 `-` はリテラルに畳み込む**（`Neg` ではない）＝`-128: I8`（最小値）が書ける。`-x`（変数・式）は通常の `Neg`。
- 演算子＝トレイト（`+`=`Add[Rhs]`、`%`=`Rem` …）だが、**`&&`/`||` だけは短絡する制御フロー**（トレイト非・Bool 専用・`if` 糖衣）。`Neg`/`Not` は eager でトレイトのまま（`Neg` は符号付き整数/浮動小数のみ＝`U*` は `-x` がコンパイルエラー）。
- **演算子・比較・step トレイトの要求は `assoc fn`（メソッドでない）**：`a+b ⟺ T.add(lhs: a, rhs: b)`・`a==b ⟺ T.eq(lhs:, rhs:)`・`a<b ⟺ T.compare(lhs:, rhs:)`・`-x ⟺ T.neg(value: x)`。命名規約＝**破壊は `inout fn`（命令形：`next`/`sort`）／非破壊で値を産む対称操作は `assoc fn`（操作名：`add`/`compare`）／名詞アクセサは `fn` メソッド（`iterator`/`count`）**。理由：非破壊なのに命令形メソッド（`a.add(rhs:)`）は「add したら a が変わる」と誤読（Swift `sort`/`sorted` 規約）。対象＝算術/ビット/`Neg`/`Not`/`BitNot`/`Eq`/`Ord`/`Coalesce`/`Pow`。非対象＝`Index`/`IndexSet`/`Chain.chain()`（アクセサ・メソッド）・`From`（factory）・`Iterator.next`（inout 破壊）。`+=` 等は演算子レベル純粋脱糖で不変 → [design-decisions.md](design-decisions.md)。
- **イテレータ・プロトコル**：`Iterator { type Item; inout fn next() -> Optional[Item] }`／`Iterable { type Item; type Iter: Iterator[Item = Item]; fn iterator() -> Iter }`。`Iterator`→`Iterable` は blanket（`iterator(){ self }`＝コピー返し）。**`for val x in e`** ⟿ `mut val it = e.iterator(); loop { match it.next() { Some(val x)=>…, None=>break } }`。`type Iter: Iterator[Item = Item]`＝**境界内の関連型束縛**を一般許可（`any Iterator[Item=I32]` と同形）・`Iter` 具象露出で単相化。提供メソッド（map/filter…）は**ベア `impl Iterator`**（準拠 `impl T as Iterator` で自動随伴・境界でも使える）・署名 core-lib。**`Step: Ord`**（assoc fn 3 本・歩数は `U64`）＝`stepsBetween(start,end)->(lower: U64, exact: Optional[U64])`〔sizeHint 同形・None=U64超過/無限〕・`stepForward(start, count: U64)->Optional[Self]`〔None=正常終端〕・`stepBackward`。レンジは `where T: Step` 条件付き準拠で `Iterable`。**Distance を associated にせず U64+tuple（Rust 踏襲）**＝Array 容量も U64 上限ゆえ正確カウントの U64 頭打ちが正しい・Swift signed Stride は UInt full-range で trap する wart → [design-decisions.md](design-decisions.md)。
- **codegen の罠**：整数オーバーフロー・整数 0 除算は**全ビルドで panic**（意味論を変えるリリースビルドは無い・wrap は `wrapping*` メソッド明示〔専用演算子 `&+` なし・整数分類トレイト内のメソッド〕）。NaN を `==`/`<` 等で比較すると **panic**（静かに `false` を返さない）。整数剰余 `%` は truncated（被除数の符号）・`Rem` は**整数のみ**で float 非提供。float `/0.0` は IEEE inf。**`assert`** は常時 ON の通常関数（条件偽で panic・全ビルド同意味論・非 lang item で import 要・`debugAssert` 除去段は additive 保留）。**数値トレイト分解**：struct 固有でない共有能力は trait 化＝原子トレイト（外部型が独立実装しうる能力＝演算子・`pow`=`Pow[Exp]`）＋分類トレイト（`Integer`/`Float`… は原子の supertrait 束＋固有要求〔`countOnes`・`wrapping*`〕）。正確なメンバ/署名は core-lib 送り → [design-decisions.md](design-decisions.md)「数値トレイトの分解原理」。
- **優先順位は Rust 準拠の 14 段**（`as` ＞ `*/%` ＞ `+-` ＞ シフト ＞ `&` ＞ `^` ＞ `|` ＞ `??` ＞ 比較 ＞ `&&` ＞ `||` ＞ レンジ）。罠：(a) **`as` は算術より強い**（`a as I64 + b` ＝ `(a as I64) + b`）、(b) **前置 `try`/`await` は後置チェーン全体を取る**（`try a.b()` ＝ `try (a.b())`・途中取り出しは `(try a).b()`）、(c) **`??` は Swift 位置＝算術より弱い**（`count ?? 0 + 1` ＝ `count ?? (0+1)`・右結合）、(d) **比較・レンジは非結合**（`a < b < c` 等は構文エラー）、(e) **ビット演算子**＝シフト>&>^>|・全部比較より上（C のバグ回避）、(f) `!`＝Bool 専用 Not・`~`＝整数 BitNot で別物。代入は文なので優先順位に乗らない。
- **複合代入は純粋脱糖・専用トレイトなし**：`a OP= b` ⟺ `a = a OP b`（Rust の `AddAssign` 等は持たない＝所有権が無く脱糖で一様に書けるため）。対象は Rust の 10 個全部＝算術 `+= -= *= /= %=`（`%=` は `Rem` が整数のみ）＋ビット系 `&= ^= |= <<= >>=`。`&&=`/`||=` は無し（短絡制御フローでトレイト非）、`??=` も無し（additive 保留）。罠：(i) **`Output` が左辺型と一致しないと型エラー**（暗黙変換なし＝複合代入で型は変わらない）、(ii) **左辺の場所は 1 回評価**（`arr[f()] += x` は `f()` 一度・`Index`→演算→`IndexSet` に展開）。

### トレイト・準拠 → [spec/08](../spec/02-type-system/08-traits.md)
- **準拠は全要求 `via` 明示**（暗黙準拠なし・`via` 左辺は常に完全シグネチャ・空 impl は準拠失敗）。「名前が合うだけで witness」のうっかり準拠を排除。
- **提供メソッド（`map`/`filter` 等）は「トレイトと同じモジュールのベア `impl Trait`」に書く**（要求＝トレイト本体〔本体なし〕／提供＝`impl Trait`〔本体あり〕＝型の struct↔impl Type の対称）。準拠 `impl A as Trait` で自動でベアに載り、境界 `where T: Trait` 越しにも使える。第三者追加は `extension { impl Trait }`＝`#Ext` opt-in。**衝突＝同名提供メソッドがベアに2つ＝併存可・曖昧なベア呼びだけエラー**→ `a#P.foo()`/`a#Q.foo()` で源選択（具体・generic 同一）。ベア既定は片方を拡張/inherent で privileged（任意）。曖昧化 **`a#P.foo()`**（`#`＝メソッド源セレクタ＝トレイト | 拡張・トレイト形は呼び出し位置限定・`A#P` 型は作らない・ここだけ一意解決を緩める）。上書き不可。**規定拡張・境界随伴・strip-on-trait は全廃**（`#!` は value/型レベルの拡張剥がし `a#!Ext`・super `self#!Bar` だけ）。
- 継承 `trait Sub: Super` は**制約のみ・自動実装しない**（`impl T as Super` が別途要る）。複数指定は `+`。
- **トレイトを値型にできるのは存在型 `any P` だけ**（裸 `P` 不可・`some` 無し・異種混在・動的）。形成は全型引数/関連型を束縛必須。呼べるメンバはメンバ単位診断（`Self` 入力位置・関連関数は不可）。**ダウンキャストは無い**（具体型/別トレイトを取り出す機構なし＝Rust 同姿勢・`as` は infallible 固定で載らない・閉集合は列挙型＋網羅 match が担う・additive 保留）。**実装は最終フェーズ**。

### 拡張 → [spec/09](../spec/02-type-system/09-extensions.md)
- **`A#P` は実行時ゼロコストのビュー**（`A` と同一構造体）だが、型検査では `A` の**不変な型細別**。ビュー変更は常に `#`/`#!` 明示＝暗黙キャストなし・**コンテナ非伝播**（`Array[A]`↔`Array[A#P]` 不可）。拡張違いは別の具体型＝オーバーロード共存（exact 一致）。
- **拡張内 `self` の型は `Foo#Bar` 固定**（呼び出し側の `#A` は本体から不可視）。帰結＝`self.m()` は `#Bar` ビューでの**再帰**（元メソッド呼びではない）、元へは `self#!Bar.m()`（"super" 相当）。
- 継承・ネスト禁止（由来一意性のため）。`T#P` 自体は準拠を主張しない（à la carte 適用）。

### 文字列・配列 → [spec/02](../spec/01-basics/02-basic-types.md)
- `String` は**不変・UTF-8 妥当・`==` バイト等価**。内部は `pub(get) bytes: Array[U8]`（O(1) 読み取り）。`scalars`/`graphemes` はイテレータ（O(n)）・**整数添字 `s[i]` は無い**。
- `Array[T]` 一本（`[E; N]`/Slice/substring は当面なし＝additive 保留・FFI は境界コピー）。**添字 `arr[i]` は `Index[U64]`・`count`・`0..<arr.count` のレンジ要素も `U64`** に統一（暗黙変換なしゆえ同型にしないとキャスト地獄）＝`for val i in 0..<arr.count { arr[i] }` がキャストレス。符号なしで負添字は表現不可・範囲外 panic。**ポインタ幅 `USize` は採らず固定 `U64`**（全ターゲット同一意味論＝Plew の「意味論を変えるビルドなし」と整合・`I32` の 2³¹ 上限も回避）。`String.bytes` は `Array[U8]` なので同じく `U64` 添字。タプルは**ラベル付き無名レコード**（構造的・振る舞いなし）。レンジは `a..<b`/`a..=b` の 2 型への固定 JSX 糖衣・反復は `Step`（整数のみ）。
- **辞書 `Dictionary[K, V]`**：リテラル `[k:v]`/`[:]`（可変アリティで JSX 不可＝配列と並ぶ本物の例外）・**lang item**（リテラルが参照）・キー `K: Hash`（`Hash: Eq`）・**`dict[k] -> V` で欠落 panic**（`Array` 範囲外と同じ＝添字の意味を型で変えない）・安全引きは `get(key:) -> Optional[V]`・代入は挿入/更新（`IndexSet`・`V`）・削除 `remove(key:)`・反復順未規定。集合 **`Set[E]`**（`E: Hash`）はリテラル無し＝**非 lang item**（import 要）。`Hash` 算法は Rust 流 `Hasher`（方向確定・正確なシグネチャは core-lib 送り）。

### モジュール・可視性 → [spec/15](../spec/04-execution/15-modules.md), [spec/05](../spec/02-type-system/05-structs-enums.md)
- **ユーザーは ambient／グローバルな定義を作れない**（全定義はモジュールスコープ・他モジュールは `import` 必須）。ただしトップレベル関数・トップレベル変数（`val`/`mut val`）は在る。static は `assoc fn`/`assoc val`。
- **import 必須の唯一の例外＝言語アイテム（lang item）。ただし ambient は型のみ・トレイトは含めない**：構文が意味として参照する**型**（数値型・`Bool`・`String`・`Array`・`Dictionary`・`Optional`/`Result`・レンジ 2 型・`Promise`・スレッドハンドル `JoinHandle`）は常にスコープ＝キーワード同格の語彙（型注釈に名前を書く＋リテラルが生む型だから）。**トレイトは非 ambient**：演算子・構文→トレイトの対応（`+`↔`Add`・`for`↔`Iterator`/`Iterable`・`xs[i]`↔`Index`・`[k:v]` キー境界↔`Hash`）は**コンパイラ内部の脱糖表（名前空間でない）**で、use site（`a+b`/`for`/`xs.sort()`）はレシーバ型＋`#Ext` で解決しトレイト名を**一度も名指さない**＝import 不要。トレイト名が要るのは `where T: P`/`any P`/`impl` の定義地点だけ（組み込み演算子トレイトも std から import）。`From` は脱糖表だが名指し時 import／`TryFrom` は構文非参照で普通の import（「脱糖表に居るか」と「名前空間に居るか」は独立）。それ以外（`Random`/`Set`/`print`）は明示 import（`@Std/…` から。判定は「構文が参照するか」で sharp。`Set` はリテラル無しゆえ非 lang item）。`Unit` 型は無い（`()` は無名レコード構文）。正確な ambient 型一覧は TODO。
- **import は 3 ルート＝`@…`（自分の外＝std か他人・名前で判別）／`/…`（自前・`src/` ルート起点の絶対）／`./`・`../`（自前・ファイル相対）。bare 名禁止**（行頭記号で provenance 確定）。**`/` は Rust の `crate::` 相当**＝深いネストで `../../` が積むのを避けるルート絶対パス（`/Models/User`＝`src/Models/User.pw`・`/` 単体＝`src/_.pw`）。**リファクタ安定**＝相対は import する側の位置を、`/` はターゲットの同一性をエンコードするので import 側を動かしても壊れない（ターゲット側を動かせば変わる＝`public` の path=file と同じ Go 流の正直さ）。**`/` は自パッケージ内ゆえ `public` ゲートを通らず到達範囲は `./`／`../` と同じ**（違いはルート絶対かファイル相対かだけ）。運用指針＝**近接は相対・遠隔/深いネストは `/`**（Rust の `super::`/`crate::` と同じ二系統）。`import`/`export`/`part` は経路文法共有ゆえ `/` はいずれでも書ける。**`@Std` は予約**（マニフェスト束縛不要・std は分割＝`@Std/Http`・`@Std/Testing`）、それ以外の `@Name` はマニフェスト束縛の外部依存。**任意深さサブパス**（`@Dep/Foo/Bar`・`@Std/Http/Server`）。**パッケージは複数モジュール公開可**＝マニフェストの **`public`（実パス列挙・既定 `["_"]`＝ルート `src/_.pw`・`_`＝ルート・`[]` 封印・ディレクトリ糖衣可）**で宣言、**列挙外は到達不可**。**公開パスは実ファイル（rename しない＝Go 流の正直さ・別名公開は additive）**。自前（`/`・`./`／`../`）とパッケージ `@…` は解決規則同一（`_.pw`＝ルート・`/`＝サブ）で、差は外部の `public` ゲートのみ（encapsulation が part→export→public で 1 段ずつ）。
- 可視性は `pub`/`pub(get)`（型スコープ・2段・中間段なし）と `export`（モジュール境界）の**別 2 軸**。非公開（修飾なし）は**その型の無名 impl からのみ**可視。
- 無名 impl は**型を定義したモジュール内のみ**置ける。外部型への実装はトレイト所有を問わず拡張 `#Ext`。
- **テスト＝`test` ブロック**（関数でない・Zig/D 流）→ [spec/15 § テスト](../spec/04-execution/15-modules.md#テスト)。配置＝**モジュール直下／無名 impl 内**（型の非 pub は無名 impl 内で白箱試験・`part` で別ファイル可・テストに特権可視性なし）。**発見＝無条件全収集**（Zig の参照ベース trap を回避＝書いたテストは必ず走る）。**production リンク除外**（通常コードは不変＝`cfg(test)` 不採用）。**アサーション＝`@Std/Testing` の `expect`/`expectEq`/`expectNe`/`expectApprox`**（`expected:`/`actual:` ラベル必須で引数逆転を防ぐ・**power-assert 不採用**＝対応範囲を関数リストで明示）。実行時 `assert`（本番・panic・常時 ON）とは別物（`expect*`＝ランナー続行）。`expectError` 不要（`expectEq`＋`isError`＋`match` で吸収）。失敗チャネル/`Debug` トレイト/`assert` 置き場は core-lib 未決。
- **トップレベル/`assoc val` の初期化（罠）** → [spec/15 § トップレベル初期化](../spec/04-execution/15-modules.md#トップレベル初期化と実行順序)。起動時 **eager**（Swift/Rust 流の遅延ではない＝`main` 前に全完了）。順序は **force-on-read で依存順を自動算出**（静的依存解析を持たない＝各値は memoize サンク・読めば相手を再帰 force）。**循環はコンパイル時でなく起動時の panic**（初期化中への再入／async ではデッドロック検出）。**トップレベルはイベントループ上の async コンテキスト**＝top-level await 可・初期化子内 `spawn`+`join()` 可・独立な非同期初期化子は並行起動（`Promise.all` 相当）で待ちが重なる。初期化子は const 限定でなく**任意の実行時式**。**同期プログラム（await 皆無）は無税**＝従来の同期 before-main と同挙動。保証は①メモリ安全（半初期化を観測しない）②依存順③一回性のみで、**独立初期化子の副作用順は unspecified（UB ではない）**＝特定順が要るなら明示依存を作る。実装：value に 未初期化/初期化中/初期化済み の状態。
- **実行エントリ＝`fn main`** → [spec/15 § 実行エントリ](../spec/04-execution/15-modules.md#実行エントリmain)。開始点は `fn main`／`async fn main`（async 任意・同期無税）。**トップレベル文は持たない**（命令的開始を `main` に分離）。実行は **①全トップレベル/`assoc val` 初期化 → ②`main`**。**戻りは `()` か `Result[(), E]`**（後者で `main` 内 `try` 可・`Err` は表示して非ゼロ終了）。**引数/環境は仮引数でなく stdlib**（`import @Std/Process`→`Process.args()`・`print`/`Random` と同じ「ambient 能力を import で明示取得」・非 lang item）。**選択は 2 段＝ビルドでファイル明示＋その中の `main`**（探索なし・`bin/` なし＝モノレポ複数エントリが同一モデル共有）。**終了は main 返却＋イベントループ drain**（保留タスク/タイマ/リスナ/未 join spawn が無い・Node/ブラウザ流＝UI は mount して return でループ生存）。`main` は実行可能ビルドのみ必須（ライブラリ不要）。

### 並行性 → [spec/14](../spec/04-execution/14-concurrency.md)
- ランタイムは **ARC**（循環は `WeakRef`）。**借用は async/spawn 境界を越えない**（越えるのは move/copy/Ref）。**spawn は move/copy のみ・`Ref` は spawn 不可**（推移的に `local` でないこと＝Ref-free を要求）→ **スレッド間に共有可変が無く実質 race-free**。**async は単一スレッドゆえ `Ref` 可**（interleave は JS 同様の論理ハザード）。
- **CoW 値は spawn 境界で eager に実体化（ディープコピー）する罠**：`Array`/`String`/`Dictionary` は `Ref` を含まず `local` でないので spawn を越えられるが、**バッファの参照カウントも非 atomic**。遅延コピーのまま越えると `Ref` と同じ競合（2 スレッドが同一バッファの count を触る）になるので、**spawn 境界では CoW の遅延を打ち切りバッファを実体化**して各スレッドに独立 count を持たせる（async では遅延のまま＝単一スレッドで安全）。ARC を全面 atomic 化せず軽量 `Ref` を保つための選択（spawn は稀・重い前提）→ [spec/14](../spec/04-execution/14-concurrency.md#cow-値は-spawn-境界で実体化するeager-copy)。
- ベア `spawn { }` はコピー可能のみ暗黙キャプチャ・`unique` は `spawn fn` の `move` 引数で渡す。`async fn`/`spawn fn` は `-> Promise[T]`/`-> JoinHandle[T]` 明示で `return e` を自動 wrap。`spawn` の戻りハンドルは `JoinHandle[T]`（`join() -> Promise[T]`・名は役割＝「join するハンドル」由来・Rust 同名）。**`join()` は panic を `Result` 包みしない**（panic はプロセス停止＝捕捉対象なし・Rust の `join()->Result` と対照）＝失敗をスレッド単位で扱うなら `spawn fn …-> Result[T,E]` を自分で返す（→ `join():Promise[Result[T,E]]`）。
- **実装課題**：境界越えの move/copy/Ref 判定（借用は越えない・`local`-free＝spawn 可否）の型検査。

### エラー → [spec/13](../spec/03-expressions/13-error-handling.md)
- `try <expr>` は `Result` の早期 return 糖衣（特別な例外機構ではない）。**`Result` 専用で `Optional` には効かない**（罠：Rust の `?` は Option でも効く）＝`Optional` は `??`/`?.`/`match`/`guard` で扱い、エラー伝播したいなら `opt ?? <Result.Err …/>` で明示 `Result` 化してから `try`（「欠落 None」と「失敗 Err」を構文で混同しない）。エラー型は `From[Source]` 実装があれば自動変換（`try` が `<E from=… />`＝From の無名 factory を挿入）。集約 enum の `From` 群はメタプログラミングで生成。
- `x as T` ⟺ `<T from=x />`（変換は常にターゲット側 `From[Source]` の **無名 factory**〔ラベル `from`〕・ソース型でオーバーロード解決）。**`as` は infallible 固定**＝`From` は全域変換だけ（無損失＋浮動小数の規定丸め）。**縮小・パース等の可謬変換は `TryFrom[Source]` の `result[Error] factory convert`** ＝ `<T.convert from=… />` で `Result[Self, Error]`（`as` 糖衣なし・silent truncate しない）。判定基準＝「必ず値を作れる＝From／表現できない入力があり得る＝TryFrom」。From は共通＝無名 factory ＋`as`、TryFrom は稀＝名前付き `convert` の非対称で、同じ Source で両方書いても衝突しない。
- **既定 factory（memberwise）とフィールド既定値**：`<Type field=…/>` の全フィールド生成はコンパイラ提供の**既定 factory**（コア構築意味論＝derive ではない）。**フィールドは宣言時既定値を持てる**（`val age: I32 = 0`）＝既定 factory のデフォルト引数の糖衣で意味論は #04 と同一（呼び出しごと再評価・定義側モジュール評価・**他フィールド/self 参照不可**）。**既定 factory の既定可視性は not pub**（無名 impl のみ＝非公開フィールドを構築引数に晒すため無制限公開はカプセル化を破る）。公開は**無名 impl 内の裸 `pub factory`**（素の構文・`@[...]` ではない）で、**既定値を持たないフィールドが全 `pub` のときだけ**可（公開版の引数は pub フィールドのみ・非公開は既定値固定）。**`@[DefaultFactory(pub)]` ディレクティブは廃止**（可視性制御は derive でなく構文＝祝福ディレクティブを作らない）→ [spec/05](../spec/02-type-system/05-structs-enums.md#既定-factorymemberwiseとフィールドの既定値)。
- **生成は常に factory（JSX 可視）の罠**：インスタンス構築は `<Type … />`／factory に集約され、構築点が一目で分かる。**失敗し得る生成は fallible factory**＝前置 `optional factory`（→ `Optional[Self]`）／`result[E] factory`（→ `Result[Self, E]`）。包めるのは Optional/Result の 2 つだけ（lang item）・自動ラップなし（本体が `Some/None`・`Ok/Err` を JSX で明示）。**`From`/`Chain`/`TryFrom` の構築要求（無名 `(from:)`／`fromValue`／`empty`／`convert`）はすべて factory 要求**（assoc fn ではない＝旧 spec の `assoc fn` 記述は誤り・修正済み）。トレイトは factory も要求できる。`optional`/`result` は**文脈依存キーワード**（factory 修飾位置のみ・`val result` は従来どおり可）→ [spec/05](../spec/02-type-system/05-structs-enums.md#失敗し得るファクトリfallible-factory), [spec/12](../spec/03-expressions/12-operators.md#失敗し得る変換tryfrom-トレイト)。
- **leading-dot 構築 `<.…/>`**（Swift `.foo`/Zig enum literal 系）：構築型が文脈から一意なとき `<Type.Member …/>` の `.` 前の型を落とせる（`<.Some value=…/>`・`<.foo n=…/>`）。**leading-dot は既存 `.` の前の型を省く操作で `.` を発明しない**＝memberwise `<Type field=…/>` には `.` が無く `<. …/>` は省略でなく捏造ゆえ不可。**`.` は常に `<.` でしか始まらない不変条件**で裸 `.foo` が浮かず構文的に一意（他言語が稀なのは裸 `.foo` の名前解決を期待型へ依存させる双方向化が要るため・Plew は `<.` 限定でパース層の曖昧さを消す）。型名は注釈/シグネチャにローカル明記＝ambient でなく provenance 回収可＝補完であって忖度でない。**使えるのは期待型が一意な位置のみ**（注釈・宣言済み戻り型・型単一の引数／leading-dot 式自身では期待型を決めない）。**型オーバーロード不可・ラベルオーバーロード可**。**パターン（`Enum.Variant{…}`・非 JSX）には波及しない** → [spec/05](../spec/02-type-system/05-structs-enums.md#型を文脈から省くleading-dot-構築)。
